# Content API

The product catalogue (categories, products, brands) and the industries served live in [Sanity](https://www.sanity.io).
Editors manage it in Sanity Studio; the website reads it from Sanity's public HTTP API.
Anyone can read the same data with a plain HTTP GET. No token is needed and none is ever used by the site.

> **The dataset is public.** Everything in it can be read by anyone who knows the project ID.
> Never store private data (customer details, prices you don't want published, internal notes) in it.

## One-time setup

Already done for `qvpsa1zr`. Repeat these steps for a new project.

1. At [sanity.io/manage](https://www.sanity.io/manage), create a project on the free plan and a dataset named
   `production` with **public** visibility.
2. Put the project ID in `sanity.project.json`.
3. Install the Studio and sign in (each person signs in themselves):
   ```bash
   cd studio
   npm ci
   npx sanity login
   ```
4. Add CORS origins. Without them, every browser request from the site returns 403:
   ```bash
   npx sanity cors add https://roguemg.github.io --credentials
   npx sanity cors add http://localhost:5173 --no-credentials
   npx sanity cors list
   ```
   The Studio needs `--credentials` because it signs editors in. `http://localhost:3333` (Studio dev server) is
   usually added when the project is created; check the list.
5. Import the starter content. `--missing` skips documents that already exist, so this never overwrites edits:
   ```bash
   npm run seed:build
   npm run seed --prefix studio
   ```
6. Invite editors at sanity.io/manage → project → **Members**. They sign in to the Studio URL above.

Pushing to `main` builds the site and, when `projectId` is set, the Studio into `dist/studio`.

## Content model

### Category (`category`)

| Field | Type | Notes |
| --- | --- | --- |
| `title` | string | Required |
| `slug` | slug | Required, generated from the title. Page URL is `/products/<slug>` |
| `eyebrow` | string | Short label above the title on cards, e.g. "Safety Footwear" |
| `summary` | text | Up to ~180 characters |
| `image` | mediaImage | Required |
| `showOnHome` | boolean | Defaults to `true`. Hidden categories still have pages |
| `order` | number | Defaults to `100`. Lower first |

### Brand (`brand`)

| Field | Type | Notes |
| --- | --- | --- |
| `name` | string | Required |
| `slug` | slug | Required |
| `tagline` | string | What the brand covers, e.g. "Power Tools" |
| `confirmed` | boolean | Defaults to `true`. `false` shows "confirmation pending" on the home page |
| `inHouse` | boolean | Defaults to `false`. The company's own range |
| `description` | text | One line shown on the Brands page |
| `logo` | mediaImage | Optional |
| `order` | number | Defaults to `100` |

### Industry (`industry`)

| Field | Type | Notes |
| --- | --- | --- |
| `title` | string | Required |
| `slug` | slug | Required |
| `label` | string | Short name used on tabs, e.g. "Energy" |
| `summary` | text | Up to ~200 characters |
| `image` | mediaImage | Required |
| `showOnHome` | boolean | Defaults to `true` |
| `order` | number | Defaults to `100` |

### Product (`product`)

Fields are grouped in the Studio as **Basics** and **Details**.

| Field | Group | Type | Notes |
| --- | --- | --- | --- |
| `title` | Basics | string | Required |
| `slug` | Basics | slug | Required. Page URL is `/products/<category slug>/<slug>` |
| `category` | Basics | reference → category | Required |
| `brand` | Basics | reference → brand | Optional |
| `summary` | Basics | text | Up to ~220 characters |
| `images` | Basics | mediaImage[] | At least one. The first is the main image |
| `isSample` | Basics | boolean | Shows a "details to be confirmed" note |
| `order` | Basics | number | Order within the category |
| `keyFeatures` | Details | string[] | |
| `description` | Details | Portable Text | Paragraphs, `h3` headings, bullet lists, bold, italic |
| `specifications` | Details | `{label, value}[]` | Rendered as a table |
| `variants` | Details | string[] | Sizes, colours etc., entered as tags |

## Images: upload or link

Every image field uses the `mediaImage` object, so editors can either upload a file or paste a link:

```json
{
  "_type": "mediaImage",
  "upload": { "_type": "image", "asset": { "_type": "reference", "_ref": "image-…" } },
  "url": "https://example.com/photo.jpg",
  "alt": "Orange safety helmet"
}
```

- At least one of `upload` or `url` is required. `alt` is strongly recommended (the Studio warns if it's empty).
- Queries return `{ "src": string | null, "alt": string }`, where `src = coalesce(upload.asset->url, url)`.
  An upload wins over a link.
- Uploaded images are served from `cdn.sanity.io`. The site adds `?w=<width>&fit=max&auto=format` and a
  `srcset` to these. Linked images are used as-is.
- The starter content links to images on the live site (`https://roguemg.github.io/mstradingco/images/…`).

## Endpoint

```
GET https://{projectId}.apicdn.sanity.io/v{apiVersion}/data/query/{dataset}?query={GROQ}&${param}={JSON value}
```

- `apicdn` is the cached CDN endpoint. Use `api.sanity.io` instead for uncached reads, e.g. right after publishing.
- Parameter values are **JSON-encoded** and then URL-encoded: `$slug="body-ppe"` becomes `%24slug=%22body-ppe%22`.
- The response is `{ "query": "…", "result": <data>, "ms": 3 }`. Only **published** documents are returned.

### Queries

All queries are in [`src/lib/content/queries.ts`](../src/lib/content/queries.ts). Shapes are in
[`src/lib/content/types.ts`](../src/lib/content/types.ts). Optional arrays come back as `[]`, and flags come
back with their defaults, never `null`.

| Export | Parameters | Returns |
| --- | --- | --- |
| `categoriesQuery` | none | `Category[]`: every category in display order, each with `products: ProductCard[]` |
| `categoryQuery` | `$slug` | `Category \| null`: one category with `products: ProductCard[]` |
| `productQuery` | `$category`, `$slug` | `Product \| null`: matches only if the product is filed under `$category`. Includes `related: ProductCard[]` (up to 3 others from the same category) |
| `brandsQuery` | none | `Brand[]` in display order |
| `industriesQuery` | none | `Industry[]` in display order |

Key shapes:

```ts
ContentImage  = { src: string | null; alt: string }
ProductCard   = { id, title, slug, summary, image: ContentImage | null,
                  brand: { name, slug } | null, category: { title, slug }, isSample }
Product       = ProductCard & { images: ContentImage[], keyFeatures: string[],
                  description: PortableTextBlock[], specifications: { label, value }[],
                  variants: string[], related: ProductCard[] }
Category      = { id, title, slug, eyebrow, summary, image, showOnHome, order,
                  products: ProductCard[] }
Brand         = { id, name, slug, tagline, description, confirmed, inHouse,
                  logo: ContentImage | null, order }
Industry      = { id, title, slug, label, summary, image, showOnHome, order }
```

### curl example

```bash
curl -G "https://qvpsa1zr.apicdn.sanity.io/v2026-10-18/data/query/production" \
  --data-urlencode 'query=*[_type == "product" && category->slug.current == $category]{title, "slug": slug.current, "brand": brand->name}' \
  --data-urlencode '$category="body-ppe"'
```

## Document IDs: never use dots

Sanity treats any document ID containing a `.` as private: it is hidden from unauthenticated (public) reads.
Drafts (`drafts.…`) rely on this. An import of `product.helmet` succeeds and shows up in the Studio and the
authenticated CLI, but **the website sees nothing**.

Use dashes: `product-helmet`, `category-body-ppe`, `brand-3m`. `scripts/build-seed.ts` refuses dotted IDs,
and `npm run test:queries` checks for them.

When verifying content, query the **public** endpoint (the curl above), not `npx sanity documents query`,
which is authenticated and can see hidden documents.

## Adding fields to existing documents

`npm run seed --prefix studio` only creates documents that don't exist yet, so new fields on existing
documents need a backfill. `studio/scripts/backfill-brand-descriptions.ts` is an example: it uses
`setIfMissing`, so it never overwrites edits made in the Studio.

```bash
cd studio
npx sanity exec scripts/backfill-brand-descriptions.ts --with-user-token
```

## Free plan limits

The project is on Sanity's free plan, which caps API requests, bandwidth, documents, assets and seats.
Check the current numbers at [sanity.io/pricing](https://www.sanity.io/pricing). The site reads through the
API CDN and caches each request in the browser session, which keeps usage low.

## Testing queries

```bash
npm ci --prefix studio   # provides groq-js
npm run seed:build
npm run test:queries
```

This runs every query against `sanity/seed.ndjson` with `groq-js` and checks the result shapes, the
wrong-category case, the related-products limit, default values, upload-over-link precedence, and that no
IDs contain dots.
